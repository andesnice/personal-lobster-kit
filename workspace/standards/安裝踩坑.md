# 安裝踩坑與快速判斷

這些條目來自接收者實際問題及製作端重現；不含收件者身分、電腦名稱、登入代碼或任何密鑰。依「看到哪一層成功」往下查，不反覆重裝。

## 1. 找不到docker／開始選單沒有Docker

- DOCKER-INSTALL只裝龍蝦，不是Docker Desktop。先跑`windows/0-INSTALL-DOCKER-DESKTOP.bat`，自己完成官方安裝、首次設定／重開機，開啟Docker Desktop，再跑DOCKER-CHECK。
- 新版找PATH、更新後的PATH及官方已知位置，但不永久改PATH。分別顯示CLI缺少、Compose缺少、引擎未啟動、Windows containers與Linux READY。
- 自動檢查已做mock；真Windows Desktop安裝仍由使用者實機驗收。

## 2. 虛擬機平台／BIOS虛擬化未啟用

- Windows optional feature與BIOS VT-x／SVM是兩件事。按Docker提示由本人啟用WSL／Virtual Machine Platform及必要重開機；BIOS路徑依實際主機板官方說明。
- 不關閉Secure Boot、TPM、防火牆或全機安全策略來碰運氣。安裝器不自動改這些設定。

## 3. READY後仍報bind mount無效，路徑在網路分享

- `\\server\share`或映射網路磁碟可能不能作為此安裝包的bind來源。新版在Windows安裝／啟動入口先拒絕UNC／映射網路分享，尚未碰Compose就顯示具體處理。
- 把**整個解壓資料夾**複製到本機磁碟，例如`D:\OpenClaw\personal-lobster`，關舊視窗，從新位置執行；不是只拿一個bat。不刪volume、不重裝Docker。
- D槽必須是本機硬碟，不是把網路磁碟換成D字母。WSL下若掛的是網路儲存仍可能失敗，不能把Windows前置檢查當成所有拓撲的保證。

## 4. C槽滿了，可以放D槽嗎

- 解壓資料夾可放本機D槽。這**不會自動搬移**Docker的映像／volume虛擬磁碟。
- 若滿的是Docker儲存空間，先備份，再依Docker Desktop版本與backend使用官方移動介面；Hyper-V／Mac／Linux的Advanced→Disk image location與WSL2情況不同，不照抄另一backend的選項。
- 不直接剪下VHDX、不unregister WSL、不刪volume。參考Docker官方設定與WSL文件。

## 5. 驗證碼要輸入哪裡／終端沒辦法點

- 終端顯示的裝置碼是給**瀏覽器的官方登入頁**使用，不是在黑色終端點輸入框。
- 使用同一個終端顯示的官方網址，登入自己的ChatGPT帳號，把當次代碼輸入網頁，回終端等`OpenAI device code complete`。不要在聊天貼代碼或QR圖。
- 過期才用`windows/DOCKER-START.bat login`重新取得當次代碼；已顯示complete就不要為了控制台畫面再登入一次。

## 6. template function "io" not defined／誤報別人的安裝

- 已重現：舊PowerShell原生命令引號傳遞會破壞Docker Go template。
- 已修：用`{{json .Config.Labels}}`再解析JSON。inspect失敗／壞JSON與真正foreign ownership分開；拒絕時不接管、不換project掩蓋錯誤。
- 舊完整包請按UPGRADE-EXISTING.md只更新啟動器，不刪任何資料。

## 7. Shared-state read and cleanup failed／GatewayLockNamespaceError

- 已重現：Gateway還在運行時另開compose run，即使共用volume仍是不同PID namespace，不能驗證owner。
- 已修：運行中讀設定、登入、models、doctor與診斷都用同容器exec；Gateway停止才允許one-off並遵守heartbeat等待。
- 這不是已證實SQLite損毀或chmod問題。不要刪鎖、reset資料庫、host PID、停其他服務或刪volume。

## 8. 誤按INSTALL會重裝嗎

- 已運行且屬本包的Gateway：INSTALL改成health／dashboard resume，不pull、不init、不重登；START不重建運行中的容器。
- 查運行狀態失敗就停止，不把查詢失敗當成「目前沒有Gateway」。離線、全新部署仍按正常初始化。

## 9. OAuth complete、health passed，但網頁說需要Gateway密鑰

- 三種東西不同：Codex裝置碼＝模型登入；Gateway token＝本機控制台憑證；device pairing＝瀏覽器／裝置配對。
- 新增`windows/DOCKER-TOKEN.bat`，只在自己的互動終端呼叫官方`gateway auth-token --show`，把顯示內容貼入**自己本機網頁的Gateway密鑰**。不要貼到聊天、截圖或筆記，不擷取到診斷log。
- Mac／Linux：`bash macos/DOCKER-START.command token`或`bash linux/docker-start.sh token`。Gateway需先運行；入口保留TTY，不用-T、不重生token。
- 若畫面是pairing required，改用`devices list`查本人瀏覽器，再精準核准；不是把裝置碼當Gateway token，也不關閉device auth。
- 上次收件者只有health與驗證頁截圖；本指南沒有冒稱已登入她的控制台或驗收真實AI。

## 10. 不知道要開哪個檔案／compose.yaml雙擊沒有反應

- 一般使用者Windows先看`README-FIRST.txt`，依編號雙擊windows裡的bat；compose.yaml是配置，不是程式入口。
- 手動命令需在compose.yaml同層開PowerShell：檔案總管上方地址列輸入`powershell`後Enter，再貼指定命令。
- 所有包都先完整解壓，不能在ZIP預覽內執行。

## 11. 沒權限／無法操作，不要先猜是模型不夠強

- 先看原始錯誤、工具實際可用性、當輪scope與執行環境；429／額度、缺工具、API拒絕、沙盒路徑不是同一原因。
- 模型備援只能用自己已授權且可用的帳號，不自動啟用付費API或放大工程師權限。

## 最後驗收：五個狀態不要混成一個成功

1. Docker CLI／Compose／Linux引擎READY。
2. 本包profile配置有效且只有自己獨立資料。
3. 自己Codex OAuth完成。
4. Gateway health通過。
5. 控制台完成憑證／必要配對，真人送一則訊息取得AI回覆。

渠道／外部工具／專案沙盒各自另驗。製作端未取得收件者最後一項成功證據，就不說全部裝好了。

## 卡住時

先執行根目錄`CHECK-SAFE.bat`（Windows）。它不修復、不重啟、不登入、不呼叫模型、不輸出設定或OAuth。只分享去敏診斷末尾；即使如此也先檢查畫面沒有自行貼上的秘密。需更多內容時只提供確切錯誤，不貼整份config／.env。
